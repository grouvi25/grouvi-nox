# VPS Sentinel

Realtime, read-only monitoring dashboard for a single VPS.
Authentication is **passkey only** (WebAuthn / Windows Hello). There is no password anywhere.

```
Browser ──https──► Cloudflare ──https──► nginx ──http──► 127.0.0.1:3999
                                  (origin locked to CF IPs)   vps-sentinel
                                                                   │ reads
                                                        /var/lib/vps-sentinel/
                                                            privileged.json
                                                                   ▲ writes
                                                        vps-sentinel-agent (root)
```

## What it shows

| Block | Data |
|---|---|
| CPU | total %, per-core %, iowait, steal, context switches, running/blocked procs |
| Memory | used / available / cached, swap usage |
| Disk | usage and inodes per filesystem, read/write throughput, device utilisation |
| Network | rx/tx rate per interface, totals, errors and drops |
| Docker | every container grouped by compose project, state, health, ports, uptime |
| PM2 | process list, status, cpu, memory, restarts, uptime |
| systemd | failed units, nginx / docker / ssh state |
| TLS | expiry for every domain served by nginx (probed over the local socket) |
| Security | fail2ban bans, SSH brute-force counters, top attacking IPs, recent logins |
| Backups | freshness and size of each backup directory |
| Alerts | threshold engine over everything above |

History for charts is kept in memory (last ~6 minutes at 2 s resolution). Nothing is persisted
except credentials and sessions.

## Security design

- **Passkey only.** No password, no TOTP, no shared secret. The private key lives in the TPM of
  your machine and cannot be exfiltrated from the server, because the server never has it.
- **User verification required** on both registration and login (PIN / biometrics / Windows password).
- **Signature counter regression** is treated as a cloned authenticator and rejected.
- **Enrollment is closed by default.** A new passkey can only be added with a one-time,
  time-limited token generated on the server (`npm run enroll`) or with a recovery code.
- **Recovery codes** are scrypt-hashed, single use, generated by `npm run recovery`.
- Sessions are HMAC-signed cookies with `__Host-` prefix, `Secure`, `HttpOnly`, `SameSite=Strict`,
  plus a server-side revocation list.
- Strict CSP (`default-src 'none'`), HSTS preload, no inline scripts, no external resources, no CDN.
- Same-origin enforcement via `Origin` and `Sec-Fetch-Site` on every state-changing route.
- Rate limits at both nginx and application level.
- **The dashboard is strictly read-only.** There is no endpoint that restarts, deletes, writes or
  executes anything. A public panel that can run commands is a backdoor with a login form.
- The service runs as an unprivileged user inside a systemd sandbox
  (`ProtectSystem=strict`, `PrivateTmp`, `RestrictNamespaces`, capped at 320 MB / 40% CPU).
- **Privilege separation.** `pm2` and `fail2ban` need root, so they are polled by a separate
  root-owned side-car (`vps-sentinel-agent`) that writes a JSON snapshot. The internet-facing
  process has **no sudo rule, no setuid path, no way to escalate** - it only reads a file.
- The origin only accepts connections from Cloudflare IP ranges.

### Known trade-off

The service account is in the `docker` group so it can read the Docker socket. Docker group
membership is root-equivalent on any host. This is the usual price for container visibility;
the alternative is a socket proxy container, which can be added later if you want it.

## Install

```bash
git clone https://github.com/grouvi25/vps-sentinel.git /opt/vps-sentinel
cd /opt/vps-sentinel
sudo DOMAIN=vps.grouvi.online bash deploy/install.sh
```

The installer creates the service user, installs dependencies, writes the sudo rules,
fetches Cloudflare ranges, issues the certificate, configures nginx and starts the unit.
It is idempotent.

## First login

```bash
cd /opt/vps-sentinel
npm run enroll        # prints a one-time https://.../enroll#token link, valid 20 min
npm run recovery      # prints 10 single-use recovery codes - store them offline
```

Open the enroll link on the machine you want to log in from, confirm with Windows Hello, done.

## Operations

```bash
npm run status              # credentials, sessions, recovery codes left
npm run enroll -- "laptop"  # add another device
node bin/enroll.js --revoke-sessions
systemctl status vps-sentinel
journalctl -u vps-sentinel -f
```

## Updating

```bash
cd /opt/vps-sentinel
git pull
npm ci --omit=dev
systemctl restart vps-sentinel
```

State in `/var/lib/vps-sentinel/state.json` survives updates. Back it up if you care about
not re-enrolling.
